## Objetivo
Implementar el login alterno con PIN (hash) con contador de intentos fallidos y bloqueo temporal
tras 5 fallos, notificando al cliente.

## Contexto embebido
- Tras 5 intentos fallidos: bloqueo temporal + notificacion.
- El bloqueo se registra sin exponer datos sensibles.
- `auth.max_failed_attempts` configurable.

## Reporte (§6 `docs/tasks/README.md`)
```
Tarea: E1-T14 - identity
Implementado: POST /auth/login/pin con PIN hasheado (PBKDF2-SHA256), contador
  failed_attempts y bloqueo temporal tras 5 fallos + login_alert; tokens/sesion
  con el mismo mecanismo que device_login (E1-T13).
CA cubiertos: CA-02 (contingencia PIN) + CA-03 (bloqueo) de HU03 + evidencia
  (backend/tests/test_pin_login.py: exito con tokens+reset; fallo incrementa;
  5to fallo ACCOUNT_LOCKED+locked_until+notificacion; bloqueo vigente rechaza
  aun con PIN correcto; bloqueo vencido permite login; inexistente/malformado
  == mal PIN mismo cuerpo y timing similar; OpenAPI expone la ruta).
Decisiones/supuestos: hasher PBKDF2-HMAC-SHA256 stdlib (210k iter, formato
  "pbkdf2-sha256$iter$salt$hash", verify con hmac.compare_digest) porque el
  .venv no trae bcrypt/argon2 y core/security.py solo tiene JWT; sin migracion
  (failed_attempts/locked_until ya existen en Credential/E1-T03);
  MAX_FAILED_ATTEMPTS=5 y LOCKOUT_SECONDS=900 como constantes candidatas a
  config.parameters (auth.max_failed_attempts/auth.lockout_seconds); rama ciega
  con hash ficticio para no filtrar por timing; ACCOUNT_LOCKED (423) sin
  exponer tiempo restante ni contadores; endpoint hace commit tambien ante
  error de negocio para que el contador persista (desviacion documentada de
  activation/device_login); notificacion login_alert/push best-effort.
Pendientes/riesgos: migrar hashes a Argon2/bcrypt cuando entren al .venv;
  mover umbrales a config.parameters cuando exista la infraestructura;
  secreto JWT de 9 bytes en local (warnings InsecureKeyLengthWarning).
Archivos/endpoints/eventos afectados: POST /auth/login/pin (401
  INVALID_CREDENTIALS, 423 ACCOUNT_LOCKED); service/pin_login.py,
  schemas/pin_login.py, api/pin_login.py (nuevos); api/__init__.py,
  schemas/__init__.py (aditivos); tests/test_pin_login.py (nuevo, 10 pruebas);
  evento auth.login_succeeded reutilizado via outbox.
```
