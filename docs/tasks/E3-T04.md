## Objetivo

Construir la pantalla del **simulador de creditos** en Flutter: seleccion de producto, sliders de
monto y plazo, opcion de desgravamen, visualizacion de la cuota, tabla de amortizacion y
descarga/compartir del PDF, presentando **solo** lo que calcula el backend.

## Alcance

- **Incluye:** feature `frontend/lib/features/credits/` (`data/`, `models/`, `presentation/`,
  `credits_routes.dart`), servicios sobre `ApiClient`, sliders, tabla de amortizacion, export,
  los 4 estados de UI y accesibilidad.
- **No incluye:** solicitud/consentimiento/estado (`E3-T09`), panel del analista (`E3-T10`),
  backend (`E3-T01`..`E3-T03`).

## Contexto embebido (decisiones que aplican)

- **Cliente delgado estricto:** el dispositivo **no** calcula cuotas, TCEA ni saldos; solo captura
  y presenta la respuesta del backend (`docs/19#1-principio`, `docs/19#4-cliente-delgado-estricto`,
  `docs/13#12-reglas-de-frontend`).
- La simulacion no mueve dinero: **no** genera `Idempotency-Key`; usar `ApiClient` normal.
- El feature NUNCA toca `lib/core/router/app_router.dart`; expone `credits_routes.dart` y el
  orquestador lo importa (`frontend/lib/features/README.md` reglas 1-2).
- Pantallas con `LoadingView`/`EmptyView`/`ErrorView` de `lib/core/widgets/`
  (`frontend/lib/features/README.md` regla 3).
- Datos sensibles enmascarados; sin API keys embebidas; sin PII en disco (`docs/13#12...`).
- UI segun tokens de `docs/20` (seccion 3-6) y los 4 estados obligatorios; PDF con `pdf`/`printing`
  (`docs/13#11-stack-y-decisiones`, `docs/20#7-estados-obligatorios-por-pantalla`).

## Modelo de datos

Sin persistencia local de dinero. Modelos Dart de respuesta: `LoanProduct`, `SimulationRequest`,
`ScheduleRow`, `SimulationResult` (cuota, TCEA, cronograma). No guardar PII ni PDFs temporales con
datos sensibles.

## API / eventos

- **Endpoints consumidos:**
  - `GET /credits/products`.
  - `POST /credits/simulate`.
  - Export PDF (ruta acordada en `E3-T03`).
- **Eventos emitidos/consumidos:** ninguno (el cliente no publica eventos).
- **Errores de negocio a mapear:** `VALIDATION_ERROR`, `NOT_FOUND`,
  `EXPORT_FORMAT_NOT_SUPPORTED` (`501`).

## Reglas de negocio

- Los sliders solo envian parametros; el backend devuelve cuota y cronograma. El cliente **no**
  recalcula nada localmente ni suma/redondea montos.
- Al mover un slider se re-simula contra el backend (con debounce); mostrar loader durante la
  peticion.
- El toggle de desgravamen reenvia la simulacion con `insurance`.
- La descarga usa el endpoint de export; si el backend responde `501`, mostrar mensaje claro.
- Montos formateados con separador de miles y moneda; sin exponer PII.

## Pruebas requeridas

- Camino feliz: flujo producto -> sliders -> cuota -> tabla -> export con servicio mockeado.
- Errores: monto/plazo fuera de rango (`422`), producto inexistente, export `501`, error de red.
- Estados vacio/carga.
- Verificar que el cliente no recalcula: la cuota mostrada es la del mock del backend.
