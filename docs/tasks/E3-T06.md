## Objetivo

Implementar el adaptador `CreditBureau` con una **interfaz comun**, una implementacion `mock`
determinista y una implementacion HTTP real, con **timeouts, reintentos con backoff y circuit
breaker**, normalizando la respuesta `{score, deudas, morosidad}` sin exponer PII.

## Alcance

- **Incluye:** `backend/app/adapters/credit_bureau.py` (interfaz + `MockCreditBureau` +
  `HttpCreditBureau`), seleccion por configuracion `CREDIT_BUREAU_PROVIDER=mock|http`, timeouts,
  reintentos con backoff y circuit breaker, errores tipados y registro en
  `backend/app/adapters/README.md`.
- **No incluye:** motor de reglas/DTI (`E3-T07`), caso de uso de solicitud y estado `EN_REVISION`
  (`E3-T08`), UI (`E3-T09`/`E3-T10`).

## Contexto embebido (decisiones que aplican)

- Los adaptadores externos viven en `app/adapters/` con interfaz comun y `mock` activable por
  configuracion; el dominio no se toca al agregar el proveedor real
  (`docs/02#9-adaptadores-externos-simulados`, `backend/app/adapters/README.md`).
- **Circuit breaker + timeouts + reintentos con backoff** en todo adaptador externo; nunca
  bloquear el hilo indefinidamente (`docs/02#8-patrones-obligatorios`).
- Score simulado **por reglas fijas por perfil** para pruebas reproducibles (D09,
  `docs/17#1-decisiones-abiertas-requieren-confirmacion`).
- El mock debe ser **determinista** (misma entrada -> misma salida); sin aleatoriedad no controlada.
- **Sin PII ni secretos en logs** (`docs/16#2` regla 7); la API key del proveedor real es variable
  de entorno, nunca en el repo (`docs/16#2` regla 10).
- Un modulo por brief: el adaptador pertenece a `credits`; no importar modelos de otros modulos.

## Modelo de datos

No persiste en este brief (el adaptador es un cliente). Datos de salida normalizados:
`BureauScore { score: int, deudas_minor: int, morosidad: bool|str }` (ajustar al contrato
`POST /score -> {score, deudas, morosidad}` de `docs/02#9...`). Montos en centimos.

## API / eventos

- **Endpoints expuestos:** ninguno publico.
- **Fachada interna:** `get_score(*, document_hash|user_id, income_minor, debt_minor) ->
  BureauScore`; el adaptador no decide, solo devuelve el dato del bureau.
- **Config:** `CREDIT_BUREAU_PROVIDER` (`mock` por defecto), `CREDIT_BUREAU_BASE_URL`,
  `CREDIT_BUREAU_API_KEY` (server-side), `CREDIT_BUREAU_TIMEOUT_SECONDS`,
  `CREDIT_BUREAU_MAX_RETRIES`.
- **Eventos emitidos:** `bureau.score.received` por outbox **solo si** el caso de uso decide
  persistirlo (nombre a registrar en `docs/18`; `docs/modules/README.md#credits` lo lista como
  consumido). Si no se persiste, no se emite.
- **Eventos consumidos:** ninguno.
- **Errores de negocio:** `BUREAU_UNAVAILABLE`, `BUREAU_TIMEOUT` (`503`/`502`); el caso de uso los
  traduce a `EN_REVISION` (`E3-T08`).

## Reglas de negocio

- Reintentos con backoff exponencial y maximo configurable; circuit breaker abre tras N fallos y
  se recupera tras una ventana.
- Timeout corto por intento; nunca bloquear el hilo indefinidamente.
- El mock devuelve score/deudas/morosidad segun reglas fijas por perfil (parametricas), sin PII.
- La seleccion mock/http se resuelve por configuracion sin tocar el dominio.
- No loggear documento, ingresos ni deuda en claro.

## Criterios de aceptacion (CA)

- `CA-03` de HU10 (parte bureau): el motor puede consultar el bureau (mock o real) y recibe
  `{score, deudas, morosidad}`.
- Los fallos del bureau provocan reintentos; agotados, el adaptador falla con error tipado (que
  `E3-T08` convierte en `EN_REVISION`).
- El mock es determinista y reproducible por perfil.

## Pruebas requeridas

- Camino feliz: `MockCreditBureau.get_score(...)` deterministico por perfil.
- Errores: timeout/error HTTP -> reintentos con backoff; agotados -> `BUREAU_UNAVAILABLE`;
  circuit breaker abre y se recupera.
- Seleccion: `CREDIT_BUREAU_PROVIDER=mock` vs `http` cambia la implementacion sin tocar llamadas.
- Sin PII: verificar que los logs/errores no contienen documento/ingreso/deuda en claro.
