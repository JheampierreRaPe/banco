## Objetivo
Implementar `journal_entries` y `postings` como estructuras append-only, con UUID por asiento y
hash encadenado, y la fachada `post_entry(...)`.

## Contexto embebido
- Cada asiento cuadra en su moneda (`sum(DEBIT)=sum(CREDIT)`).
- `postings` no admite `UPDATE`/`DELETE`.
- `hash` encadena con el asiento anterior; `reverse_entry` genera asiento nuevo.

## Context pack
- L0. L1: `docs/modules/README.md#ledger`.
- L2: `docs/04-motor-transaccional-y-ledger.md#2-contabilidad-de-partida-doble-obligatoria` y
  `#7-asientos-por-tipo-de-operacion`, `docs/03b-diccionario-de-datos.md#72-journal_entries`.

## Frontera
- Puede tocar: `ledger/domain/`, `service/`, `repository/`.
- Prohibido: ser llamado desde fuera de la fachada; los demas modulos no insertan postings.

## Modelo de datos
`journal_entries`, `postings`.

## API / eventos
- Fachada `post_entry(entries)`, `reverse_entry(entry_id)`.
- Evento `ledger.entry.posted`.

## CA
- `CA-01`, `CA-02` y `CA-03` de HU18.

## Pruebas
- Asiento cuadrado; asiento descuadrado rechazado; reverso; UUID unico; bloqueo de update/delete.

## Entregables
- [x] Dominio + fachada + pruebas.
