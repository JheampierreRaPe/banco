## Objetivo

Persistir las **excepciones** que produce el matching (`reconciliation_exceptions`) con su tipo,
diferencia y evidencia, exponer el **reporte de diferencias** al analista de operaciones
(`GET /reconciliation/exceptions`, `GET /reconciliation/runs/{id}`) y emitir
`reconciliation.exception` por `outbox`. No corrige nada: solo documenta y deja la excepcion lista
para el flujo de reclamos (`E5-T20`).

## Alcance

- **Incluye:**
  - Migracion encadenada con `reconciliation.reconciliation_exceptions` (`docs/03b#12.2`):
    `run_id FK`, `transaction_id NULL`, `clearing_item_id NULL`, `type`, `difference_minor`,
    `status`, `created_at`; `CHECK` de `type` y `status`.
  - Servicio `record_exceptions(session, run, results)` que persiste una fila por item no conciliado
    (idempotente por `run_id + clearing_item_id`/`transaction_id + type`).
  - Reporte `get_run_report(session, run_id)` y `list_exceptions(session, filters)` con paginacion
    (`page`/`page_size`, default 20/max 100), filtros `status`, `type`, `run_id`, `currency`,
    `date_from`/`date_to`.
  - Endpoints (rol `operations_analyst`/`analyst`):
    - `GET /api/v1/reconciliation/exceptions` -> `200` lista paginada, cuentas/refs enmascaradas.
    - `GET /api/v1/reconciliation/runs/{id}` -> `200` resumen de la corrida + contadores +
      excepciones agregadas por tipo.
  - Evento `reconciliation.exception` por `outbox` (payload `{exception_id, run_id, type,
    difference_minor, currency, status}` sin PII) al crear una excepcion nueva.
  - Auditoria best-effort `reconciliation.exception.recorded` (sin PII).
- **No incluye:** `claims` ni asiento de ajuste (`E5-T20`), UI (`E5-T21`), QA (`E5-T22`). No
  modifica `transactions`/`ledger` ni resuelve la diferencia.

## Contexto embebido (decisiones que aplican)

- **Tabla (`docs/03b#12.2`):** `reconciliation_exceptions(id, run_id FK, transaction_id NULL,
  clearing_item_id NULL, type, difference_minor, status, created_at)`.
- **Tipos:** `AMOUNT_DIFF`, `DATE_DIFF`, `MISSING_INTERNAL`, `MISSING_EXTERNAL`,
  `CURRENCY_MISMATCH`, `DUPLICATE`; `status` `OPEN`/`IN_REVIEW`/`RESOLVED`/`DISMISSED`.
- **Evento (`docs/02#7`):** `reconciliation.exception` lo consumen `risk`/`audit`/operaciones; se
  publica por `outbox` en la misma transaccion (regla de oro 8), nunca directo.
- **Frontera:** `reconciliation` no escribe `transactions`/`ledger`; el `transaction_id` es una
  referencia logica, sin FK fisica.
- **Matriz de accesos (`docs/13#2.2`):** solo el analista de operaciones ve excepciones/reclamos;
  el cliente nunca ve estas rutas.
- **Enmascaramiento:** la API no expone numeros de cuenta ni documentos; solo IDs y montos.
- **Dinero:** centimos enteros; `difference_minor` puede ser negativo (diferencia a favor/en contra),
  documentar el signo.

## Modelo de datos

- `reconciliation_exceptions`: `id UUID PK`, `run_id UUID FK`, `transaction_id UUID NULL`,
  `clearing_item_id UUID NULL FK`, `type VARCHAR(30)`, `difference_minor BIGINT`,
  `status VARCHAR(15)` default `OPEN`, `created_at TIMESTAMPTZ`.
- Indices: `(run_id)`, `(status)`, `(type)`, `(transaction_id)`.
- UQ parcial recomendada: `(run_id, clearing_item_id, type)` para no duplicar la misma excepcion.

## API / eventos

- **Endpoints:**
  - `GET /api/v1/reconciliation/exceptions` (Bearer, rol operaciones) -> lista paginada.
  - `GET /api/v1/reconciliation/runs/{id}` (Bearer, rol operaciones) -> resumen de corrida.
- **Eventos emitidos:** `reconciliation.exception` por `outbox`.
- **Eventos consumidos:** ninguno.
- **Errores de negocio:** `NOT_FOUND` (corrida inexistente), `NOT_AUTHORIZED` (sin rol),
  `VALIDATION_ERROR` (filtros invalidos).

## Reglas de negocio

- Cada item no conciliado produce **una** excepcion con su tipo y diferencia; no se duplica al
  reejecutar.
- `MISSING_INTERNAL`/`MISSING_EXTERNAL` llevan `difference_minor` igual al monto del item/operacion.
- `AMOUNT_DIFF` lleva la diferencia con signo (`clearing - interno`); documentarlo en el contrato.
- La excepcion nace `OPEN`; solo `E5-T20` la mueve a `IN_REVIEW`/`RESOLVED`/`DISMISSED`.
- Nada se borra: una excepcion resuelta conserva su fila y su evidencia.
- Sin PII en logs ni en el payload del evento.

## Criterios de aceptacion (CA)

- `CA-01` (HU19 CA-03): cada diferencia del matching queda en `reconciliation_exceptions` con tipo,
  monto y referencia; el reporte la lista paginada y filtrable.
- `CA-02`: reejecutar el matching no duplica excepciones (UQ/servicio idempotente).
- `CA-03`: se emite `reconciliation.exception` por `outbox` una sola vez por excepcion nueva.
- `CA-04`: solo el rol de operaciones accede; sin rol -> `403 NOT_AUTHORIZED`; sin PII en la
  respuesta.
- `CA-05`: `pytest`/`ruff`/`black` y `alembic check` en verde.

## Pruebas requeridas

- Camino feliz: corrida con 1 match + 1 diferencia -> 1 excepcion `OPEN`, reporte con contadores.
- Errores: filtros invalidos -> `422`; corrida inexistente -> `404`; sin rol -> `403`.
- Idempotencia: reejecutar la corrida no duplica excepciones.
- Evento: una fila de `outbox` por excepcion nueva; payload sin PII.
- No mueve dinero.
