## Objetivo

Construir la pantalla del **analista de operaciones** en el panel: lista de corridas con contadores,
lista de excepciones filtrable y detalle de reclamo con la accion de resolver (con o sin ajuste).
La pantalla solo **muestra y envia**; el backend decide el cruce, el ajuste y los saldos.

## Alcance

- **Incluye:**
  - Feature `admin-web/src/features/reconciliation/`: `ReconciliationRunsPage`,
    `ExceptionsPage`, `ClaimDetail` y componentes de tabla/estado.
  - Cliente API + hooks TanStack Query: `GET /reconciliation/runs/{id}`,
    `GET /reconciliation/exceptions`, `POST /reconciliation/exceptions/{id}/claims`,
    `POST /reconciliation/claims/{id}/resolve` (con `Idempotency-Key` generada en el panel).
  - Filtros (estado, tipo, fecha, moneda) y paginacion; detalle de excepcion con diferencia y
    referencias enmascaradas.
  - Formulario de resolucion: `resolution` + ajuste opcional; muestra el asiento resultante
    (`adjustment_entry_id`) y el estado final.
  - Estados obligatorios: cargando, vacio, error, contenido (`docs/20#7`); mensajes en espanol;
    datos sensibles enmascarados.
  - Pruebas de componente/estados y de envio de `Idempotency-Key`.
- **No incluye:** rutas/guards/menu global (los integra `F-T13`), backend (`E5-T16`..`E5-T20`),
  QA E2E (`E5-T22`), edicion de asientos (prohibida), diseno visual final si no hay mockup.

- **Matriz de accesos (`docs/13#2.2`):** el analista de operaciones ve corridas, excepciones,
  reclamos y ajustes; ningun otro rol.

  asientos nuevos autorizados; sesion separada de la app movil.
- **Cliente delgado (`docs/19#4`):** el panel no calcula diferencias ni decide el ajuste; muestra lo

- **Idempotencia:** la resolucion con ajuste envia `Idempotency-Key` generada en el panel; un

## Modelo de datos

Ninguno en el panel. Consume las vistas de `reconciliation_runs`,
`reconciliation_exceptions` y `claims` via API; no persiste nada localmente.

## API / eventos

- **Endpoints consumidos:**
  - `GET /api/v1/reconciliation/runs/{id}`
  - `GET /api/v1/reconciliation/exceptions?status=&type=&run_id=&date_from=&date_to=&page=&page_size=`
  - `POST /api/v1/reconciliation/exceptions/{id}/claims`
  - `POST /api/v1/reconciliation/claims/{id}/resolve` (`Idempotency-Key`)
- **Eventos:** no consume eventos directamente.
- **Errores a mostrar:** `NOT_FOUND`, `NOT_AUTHORIZED`, `CONFLICT` (claim ya resuelto),
  `VALIDATION_ERROR` (ajuste invalido) con mensaje accionable.

## Reglas de negocio

- El panel no calcula la diferencia ni el asiento: muestra `difference_minor` y
  `adjustment_entry_id` del servidor.
- No se permite editar ni borrar asientos desde la UI; el ajuste es un formulario que crea uno nuevo.
- Todo dato de cuenta/documento se muestra enmascarado; nunca se muestran UUIDs crudos al usuario
  (se usa una referencia corta).
- La accion de resolver pide confirmacion explicita y deshabilita el boton mientras envia.
- Sin logica offline; si la API falla, se muestra error y se permite reintentar.

## Criterios de aceptacion (CA)

- `CA-01`: la pantalla lista corridas y excepciones con filtros/paginacion y muestra los cuatro
  estados (cargando/vacio/error/contenido).
- `CA-02`: el detalle de excepcion muestra tipo, diferencia, referencias enmascaradas y estado.
- `CA-03`: se puede abrir un claim y resolverlo con/sin ajuste; la UI muestra el asiento resultante
  y el estado final; envia `Idempotency-Key`.
- `CA-04`: ningun control permite editar/borrar asientos; los datos sensibles estan enmascarados.
- `CA-05`: `npm test`/`tsc`/lint en verde; pruebas de estados y de envio de la clave.

## Pruebas requeridas

- Componente: render de lista con datos, vacio, error y cargando.
- Interaccion: filtro -> query actualizada; abrir claim -> POST; resolver -> POST con
  `Idempotency-Key` y manejo de `CONFLICT`/`422`.
- Seguridad: no se renderizan cuentas/documentos completos ni UUIDs crudos.
- No aplica concurrencia de dinero (la idempotencia la garantiza el backend; el panel solo envia la
  clave).

## Regla de cliente delgado (dos campos)

El panel solo **consulta y envia**: no calcula diferencias, no decide el ajuste, no mueve saldos ni
guarda estado de negocio. La unica logica local es presentacion (filtros, formato, estados) y la
generacion de `Idempotency-Key` para la resolucion; el backend es la unica autoridad.
