## Objetivo

Crear el modelo de **reglas antifraude** (`risk.risk_rules`) con prioridad, accion
(`ALERT`/`HOLD`/`BLOCK`), `enabled` y `params_json`, sembrar las reglas iniciales y exponerlas para
consulta/edicion auditada **sin reiniciar** el servicio. Es el cimiento de `E6-T02`/`E6-T04`.

## Alcance

- **Incluye:**
  - Migracion `0049_risk_rules` (revision tentativa; encadenar al head vigente) con
    `risk.risk_rules` segun `docs/03b#11.1`: `id`, `code` UQ, `name`, `enabled`, `priority`,
    `params_json`, `action`, `created_at`, `updated_at`, `updated_by`.
  - Modelo SQLAlchemy + repositorio (`list_rules`, `get_by_code`, `update_rule`) + servicio
    `evaluate_config`/`upsert_rule`.
  - Semilla idempotente de reglas iniciales (todas `enabled=true` con umbrales conservadores):
    `FACIAL_SPOOFING` (fallos biometricos), `ATYPICAL_GEO` (pais no habitual), `UNUSUAL_AMOUNT`
    (monto > `k * avg`), `VELOCITY` (N operaciones en ventana), `NEW_DEVICE` (dispositivo no visto).
  - Endpoints (rol `fraud_analyst`/`admin`):
    - `GET /api/v1/risk/rules` -> lista con `code`, `name`, `enabled`, `priority`, `action`,
      `params_json`, `updated_at`.
    - `PUT /api/v1/risk/rules/{code}` -> `{enabled?, priority?, action?, params_json?}`; valida
      accion y tipos; audita `risk.rule.updated` (sin PII); no requiere reinicio.
  - Lectura de parametros globales por `shared/config` si una regla necesita un umbral global
    (`risk.velocity_window_seconds`, `risk.unusual_amount_factor`), con fallback.
- **No incluye:** evaluacion (`E6-T02`), perfil (`E6-T03`), `alerts`/bloqueo (`E6-T04`), panel
  (`E6-T05`), QA (`E6-T06`). No mueve dinero ni emite `fraud.alert.raised` aun.

## Contexto embebido (decisiones que aplican)

- **Tabla (`docs/03b#11.1`):** `risk_rules(id, code UQ, name, enabled, priority SMALLINT,
  params_json JSONB, action VARCHAR(15) CK, created_at, updated_at, updated_by)`.
- **Acciones (`docs/11#hu20...`):** cada regla tiene prioridad y accion `ALERT` (alertar), `HOLD`
  (retener) o `BLOCK` (bloquear). El `CHECK` debe permitir exactamente esos valores.
- **Reglas configurables sin reiniciar (`docs/11`):** la evaluacion lee `risk_rules` en cada pasada;
  no hay cache en proceso obligatoria (si se cachea, invalidar al `PUT`).
- **Parametros (`regla de oro 6`):** umbrales globales en `config.parameters` via `shared/config`;
  `params_json` guarda los umbrales propios de la regla.
- **Frontera:** `risk` es dueno de `risk_rules`; no toca `transactions`/`ledger`/`accounts`.
- **Auditoria:** cada cambio de regla deja `updated_by`/`updated_at` y auditoria best-effort; sin PII.
- **Semilla conservadora:** las reglas no deben romper las suites existentes; umbrales altos o
  `enabled` configurable (decision del dueno en `E6-T06`).

## Modelo de datos

- `risk.risk_rules`: `id UUID PK`, `code VARCHAR(40) UQ`, `name VARCHAR(120)`,
  `enabled BOOLEAN default true`, `priority SMALLINT default 100`, `params_json JSONB default '{}'`,
  `action VARCHAR(15) default 'ALERT' CHECK IN ('ALERT','HOLD','BLOCK')`,
  `created_at`, `updated_at`, `updated_by UUID NULL`.
- Indices: `(enabled)`, `(priority)`.

## API / eventos

- **Endpoints:**
  - `GET /api/v1/risk/rules` (Bearer, rol fraude/admin).
  - `PUT /api/v1/risk/rules/{code}` (Bearer, rol fraude/admin) -> `200` con la regla actualizada.
- **Eventos emitidos:** ninguno de negocio; auditoria `risk.rule.updated` (best-effort).
- **Eventos consumidos:** ninguno.
- **Errores de negocio:** `NOT_FOUND` (codigo inexistente), `NOT_AUTHORIZED`, `VALIDATION_ERROR`
  (accion/prioridad/JSON invalidos).

## Reglas de negocio

- `code` es inmutable y unico; `name`/`params_json`/`priority`/`action`/`enabled` son editables.
- `priority` menor = se evalua antes; empate -> `code` ascendente (determinista).
- Una regla deshabilitada no participa en la evaluacion (`E6-T02`).
- `params_json` debe ser un objeto JSON; cada regla documenta sus claves (`threshold_minor`,
  `window_seconds`, `factor`, etc.).
- Cambiar una regla se refleja en la siguiente evaluacion, sin reinicio.
- Sin PII en logs ni en `params_json` (solo umbrales).

- Determinismo: prioridad + `code` ordenan la evaluacion.
