## Objetivo

Enriquecer el **perfil de comportamiento** del titular (`risk_profiles`) con su historial real:
monto promedio, paises/horas habituales, ultimo dispositivo y severidad acumulada. El motor de
`E6-T02` lo consulta para decidir; este brief solo **alimenta** el perfil, sin mover dinero.

## Alcance

- **Incluye:**
  - Dominio puro `risk/domain/profile.py`: `next_profile(current, observation) -> ProfileUpdate`
    con media incremental (sin `float` para montos; `Decimal`/enteros), ventana de horas
    (`usual_hours`), paises (`usual_countries`) y `last_device_id`.
  - Servicio `update_behavior(session, user_id, observation)` idempotente por
    `(event_id, user_id)` via `processed_events` (consumidor `risk-profile`), con `commit` propio
    en el handler.
  - Consumidores D-04:
    - `transaction.initiated` / `transfer.settled` -> monto/moneda/hora/pais/dispositivo;
    - `auth.login_succeeded` -> hora/dispositivo/pais (si el payload los trae);
    - `auth.failed_attempt` -> severidad (ya existe `E2-T20`; no duplicar el efecto, solo
      complementar el perfil).
  - Suscripcion en `app/composition.py` (patron `E2-T20`), con flags para no romper pruebas.
  - Endpoint de solo lectura `GET /api/v1/risk/profiles/{user_id}` (rol fraude) -> `200` con
    `avg_amount_minor`, `usual_countries`, `usual_hours`, `last_device_id`, `score`, `updated_at`
    (sin PII; `user_id` es UUID).
- **No incluye:** evaluacion (`E6-T02`), alertas/bloqueo (`E6-T04`), panel (`E6-T05`), QA
  (`E6-T06`). No mueve dinero ni crea `alerts`.

## API / eventos

- **Endpoints:** `GET /api/v1/risk/profiles/{user_id}` (Bearer, rol fraude) -> perfil minimo.
- **Eventos consumidos:** `transaction.initiated`, `transfer.settled`, `auth.login_succeeded`,
  `auth.failed_attempt`.
- **Eventos emitidos:** ninguno.
- **Errores:** `NOT_FOUND` (perfil inexistente o `user_id` invalido), `NOT_AUTHORIZED`.

## Reglas de negocio

- La media de monto se actualiza con cada operacion observada; el redondeo es entero y documentado.
- `usual_hours` guarda las horas (0-23) con actividad; `usual_countries` los paises vistos; ambos
  acotados (p. ej. top 5) para no crecer sin limite.
- `last_device_id` se actualiza con el ultimo dispositivo observado.
- `score` no se recalcula aqui salvo el ajuste ya existente de `E2-T20`; `E6-T04` lo usara para
  alertas.
- Un evento repetido no actualiza dos veces el perfil (idempotencia por `processed_events`).
- Sin PII en logs/respuestas.

## Criterios de aceptacion (CA)

- `CA-01`: tras N operaciones, `avg_amount_minor`, `usual_hours`, `usual_countries` y
  `last_device_id` reflejan el historial de forma determinista.
- `CA-02`: el perfil se actualiza por eventos, no por lectura del cliente; un evento repetido no
  duplica el efecto.
- `CA-03`: `GET /risk/profiles/{user_id}` devuelve el perfil minimo sin PII; sin rol -> `403`.
- `CA-04`: el motor de `E6-T02` puede leer el perfil actualizado (prueba de integracion).
- `CA-05`: `pytest`/`ruff`/`black` en verde; suites previas intactas.

## Pruebas requeridas

- Dominio: media incremental, horas/paises, topes, redondeo entero.
- Consumidores: cada evento actualiza lo que corresponde; replay no duplica; fallo -> rollback.
- Endpoint: perfil existente/inexistente; RBAC.
- Integracion: `E6-T02` ve el perfil actualizado.
- No mueve dinero.
