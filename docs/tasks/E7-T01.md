## Objetivo

Crear el schema `fx` con las tablas `fx_rates`, `fx_quotes`, `fx_operations`, `savings_pockets` y
`pocket_movements`, sus modelos SQLAlchemy, constraints/indices y repositorio base. Es el cimiento
de HU24 (bolsillos) y HU25 (cambio de divisas).

- **Incluye:**
  - Migracion `0053_fx` (revision tentativa; encadenar al head vigente y renumerar si otro brief
    tomo el numero) con las cinco tablas de `docs/03b#10`:
    - `fx_rates(id, base, quote, rate NUMERIC(18,8) CHECK >0, source, fetched_at, ttl_seconds)`;
    - `fx_quotes(id, user_id, base, quote, rate, spread, source_amount_minor, target_amount_minor,

## Contexto embebido (decisiones que aplican)

- **Tablas (`docs/03b#10`):** tipos exactos; `fx_quotes.status` usa `fx_quote_status`
  (`ACTIVE`/`EXPIRED`/`CONSUMED`/`CANCELLED`); `savings_pockets.status` `ACTIVE`/`CLOSED`;
  `pocket_movements.direction` `DEBIT`/`CREDIT`.
- **Dinero:** `BIGINT` en centimos; `NUMERIC(18,8)` para tasas/spread/yield; nunca `float`.
- **Frontera:** `fx` es dueno de su schema; no importa modelos de `accounts`/`transactions`/
  `ledger`; usa fachadas en los briefs de servicio.
- **Referencias logicas:** `fx_operations.transaction_id`, `savings_pockets.account_id` y
  `pocket_movements.journal_entry_id` son REF logicas (sin FK fisica entre schemas), regla de oro 4.
- **Migracion:** un solo head; `alembic check` limpio; `downgrade` reversible.
- **Sin PII:** `user_id` es UUID; no se guardan nombres ni documentos.

## Modelo de datos

Ver `docs/03b#10`:
- `fx_rates`: `id UUID PK`, `base CHAR(3)`, `quote CHAR(3)`, `rate NUMERIC(18,8) CHECK >0`,
  `source VARCHAR(40)`, `fetched_at TIMESTAMPTZ`, `ttl_seconds INTEGER default 60`.
- `fx_quotes`: `id UUID PK`, `user_id UUID`, `base`, `quote`, `rate`, `spread NUMERIC(18,8) default
  0`, `source_amount_minor BIGINT`, `target_amount_minor BIGINT`, `expires_at TIMESTAMPTZ`,
  `status VARCHAR(12) default 'ACTIVE'`, `created_at`.
- `fx_operations`: `id UUID PK`, `quote_id UUID UQ FK`, `transaction_id UUID`, `status VARCHAR(15)
  default 'EXECUTED'`, `executed_at`.
- `savings_pockets`: `id UUID PK`, `user_id UUID`, `account_id UUID NULL`, `name VARCHAR(80)`,
  `currency CHAR(3)`, `target_minor BIGINT NULL CHECK >=0`, `balance_minor BIGINT default 0 CHECK
  >=0`, `roundup_enabled BOOLEAN default false`, `yield_rate NUMERIC(18,8) default 0`,
  `status VARCHAR(15) default 'ACTIVE'`, `created_at`.
- `pocket_movements`: `id UUID PK`, `pocket_id UUID FK`, `journal_entry_id UUID NULL`,
  `movement_type VARCHAR(20)`, `direction VARCHAR(6)`, `amount_minor BIGINT CHECK >0`,
  `currency CHAR(3)`, `created_at`.

## Reglas de negocio

- `rate`/`spread`/`yield_rate` son `NUMERIC`; montos son enteros en centimos.
- `base != quote`; ambas monedas ISO-4217 de 3 letras.
- `fx_quotes.expires_at` se fija al crear (30 s en `E7-T09`); el schema no lo impone.
- `fx_operations.quote_id` es UQ: una cotizacion se ejecuta una sola vez.
- `savings_pockets.balance_minor` no puede ser negativo; los movimientos son inmutables (solo
  insercion).
- Nada se borra: `status` cambia, las filas se conservan.

## Criterios de aceptacion (CA)

- `CA-01`: existe el schema `fx` con las cinco tablas, `CHECK`/indices y migracion reversible;
  `alembic check` limpio (un solo head).
- `CA-02`: el repositorio crea/lee tasas, cotizaciones, operaciones, bolsillos y movimientos con
  validacion de moneda/montos.
- `CA-03`: una cotizacion no se puede ejecutar dos veces (UQ `quote_id`).
- `CA-04`: `pytest`/`ruff`/`black` en verde; sin PII.
