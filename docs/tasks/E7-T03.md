# E7-T03 - Redondeo automatico integrado al flujo de pago

## Objetivo

Cuando un pago/transferencia se liquida y el cliente tiene un bolsillo con `roundup_enabled`, redondear
el monto al **sol/unidad superior** y transferir el excedente al bolsillo, por el motor y el ledger
(asiento `docs/04#7.8`). Idempotente por transaccion; si no hay fondos, no se hace nada.

## Alcance

- **Incluye:**
  - Dominio puro `fx/domain/roundup.py`: `compute_roundup(amount_minor, unit_minor) -> int`
    (excedente `0..unit-1`; `amount % unit == 0` -> 0), validacion de enteros.
  - Consumidor D-04 `fx.on_payment_settled` (sesion/`commit` propios, `processed_events`
    consumidor `fx-roundup`) suscrito a `transfer.settled`, `qr.payment.confirmed`, `service.paid`
    y `topup.completed` (los que traigan `user_id`/cuenta origen; si no, se resuelve por la fachada
    de lectura de `transactions`).
  - Servicio `apply_roundup(session, *, user_id, transaction_id, source_account_id, amount_minor,
    currency)`:
    - busca el bolsillo `ACTIVE` con `roundup_enabled=true` y misma moneda del titular;
    - calcula el excedente; si `0`, no hace nada;
    - transfiere el excedente por `E7-T05` (`transfer_to_pocket`, misma moneda) con clave estable
      `roundup:<transaction_id>`;
    - registra `pocket_movements` tipo `ROUNDUP` (lo hace el traspaso) y audita
      `fx.roundup.applied` (sin PII).
  - Parametros: `fx.roundup_unit_minor` (default `100`), `fx.roundup_enabled_default` (default
    `false`) via `shared/config`.
- **No incluye:** UI de activacion (`E7-T06`), rendimientos (`E7-T04`), traspasos manuales
  (`E7-T05`), cambio de divisas (`E7-T08`..`T13`), QA (`E7-T07`). No crea un asiento nuevo: usa el
  traspaso `docs/04#7.8`.

## Contexto embebido (decisiones que aplican)

- **Logica (`docs/12#hu24...`):** al pagar se redondea al sol superior y el excedente va al bolsillo
  de ahorro.
- **Asiento (`docs/04#7.8`):** el traspaso a bolsillo es como `7.1`, usando las cuentas contables de
  la cuenta principal y del bolsillo; **no** se inventa un asiento nuevo.
- **Dinero:** centimos enteros; el excedente es `unit - (amount % unit)` (0 si ya es multiplo).
- **Idempotencia:** una transaccion produce como maximo un redondeo (`roundup:<transaction_id>`);
  replay no duplica.
- **Fondos:** si la cuenta origen no tiene saldo para el excedente, el redondeo se omite (no bloquea
  el pago original); auditar `fx.roundup.skipped` sin PII.
- **Frontera:** `fx` no escribe `transactions`/`ledger`/`accounts`; mueve por la fachada de `E7-T05`
  (que a su vez usa el motor).
- **Consumidores D-04:** `commit` propio, `processed_events`, fallo -> rollback/relanzar.

## Modelo de datos

No crea tablas: usa `savings_pockets`/`pocket_movements` (`E7-T01`) y el traspaso de `E7-T05`.
`pocket_movements.movement_type=ROUNDUP`, `direction=CREDIT`.

## API / eventos

- **Endpoints:** ninguno publico (el redondeo es automatico).
- **Eventos consumidos:** `transfer.settled`, `qr.payment.confirmed`, `service.paid`,
  `topup.completed`.
- **Eventos emitidos:** ninguno nuevo; auditoria `fx.roundup.applied`/`skipped`.
- **Errores:** no aplica al cliente; el consumidor no rompe el pago original.

## Reglas de negocio

- Solo aplica a bolsillos `ACTIVE` con `roundup_enabled=true` y misma moneda.
- El excedente se calcula sobre el monto de la operacion (no sobre comisiones).
- Si el excedente es 0, no hay movimiento ni evento.
- Si no hay fondos, se omite el redondeo (no se rechaza el pago ya liquidado).
- Un solo redondeo por transaccion; replay no duplica.
- Sin PII en logs/auditoria.

## Criterios de aceptacion (CA)

- `CA-01` (HU24 CA-02): un pago de 1,250 con unidad 100 redondea 50 al bolsillo; el asiento del
  traspaso cuadra (`docs/04#7.8`).
- `CA-02`: monto multiplo de la unidad -> no hay redondeo.
- `CA-03`: sin fondos -> se omite sin afectar el pago original; se audita `skipped`.
- `CA-04`: idempotencia por `transaction_id`; replay no duplica el traspaso.
- `CA-05`: `pytest`/`ruff`/`black` en verde; sin PII.

## Pruebas requeridas

- Dominio: 1,250/100 -> 50; 1,200/100 -> 0; montos borde.
- Consumidor: pago liquidado -> traspaso + movimiento `ROUNDUP`; replay no duplica.
- Sin fondos -> skip; bolsillo deshabilitado -> no aplica.
- Asiento cuadrado; `fx` no escribe tablas ajenas.
- Regresion: pagos sin bolsillo siguen normales.
