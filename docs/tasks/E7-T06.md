## Objetivo

Que el cliente vea sus **bolsillos y metas**, abra uno nuevo, active el redondeo y haga un traspaso
desde/hacia una cuenta o bolsillo, mostrando siempre datos del servidor. La app solo captura y
muestra; no calcula saldos, rendimientos ni redondeos.

## Alcance

- **Incluye:**
  - Feature `frontend/lib/features/pockets/`: `PocketsPage` (lista con saldo/moneda/meta/progreso),
    `PocketDetailPage` (movimientos y acciones), `PocketFormPage` (nombre, moneda, meta, redondeo) y
    `PocketTransferPage` (origen/destino/monto).
  - Cliente `data/pocket_service.dart`: `GET /pockets`, `GET /pockets/{id}`, `POST /pockets`,
    `POST /pockets/{id}/transfer` (con `Idempotency-Key` generada en el cliente).
  - Estados obligatorios: cargando, vacio, error, contenido (`docs/20#7`); mensajes en espanol;
    montos formateados desde centimos del servidor.
  - Progreso de meta (`balance_minor/target_minor`) calculado **solo para presentacion** (barra);
    si el servidor no da el porcentaje, el cliente lo deriva del monto ya recibido (no decide nada).
  - Pruebas de widget: lista/detalle/formulario/traspaso, estados y envio de clave.
- **No incluye:** backend (`E7-T02`/`T05`), redondeo/rendimiento (se muestran si el backend los
  expone; no se calculan), cambio de divisas (`E7-T12`), QA (`E7-T07`), diseno visual final si no
  hay mockup.

## Contexto embebido (decisiones que aplican)

- **Cliente delgado (`docs/19#4`):** la app no calcula saldos, rendimientos, redondeos ni decide
  traspasos; envia monto/destino y muestra la respuesta. Sin logica offline.
- **Dinero:** los montos llegan en centimos enteros; el cliente solo formatea (sin `double` para
  aritmetica de negocio).
- **Idempotencia:** el traspaso y la apertura envian `Idempotency-Key`; el servidor valida.
- **Estados (`docs/20#7`):** cargando/vacio/error/contenido en toda pantalla.
- **Banca (`docs/20#8`):** cuentas enmascaradas, objetivos tactiles >= 44px, mensajes accionables,
  nunca datos de otro cliente.
- **Navegacion (`docs/13#1.2`):** pantallas no terminales apiladas con back `pop`; raiz/tab sin back.
- **Mockup pendiente:** se construye con tokens `docs/20`/`design.md`; se registra en
  `docs/design/mockups.md`.

## Modelo de datos

Ninguno local. Consume `savings_pockets`/`pocket_movements` via API; no persiste saldos ni
movimientos.

## API / eventos

- **Endpoints consumidos:**
  - `GET /api/v1/pockets`, `GET /api/v1/pockets/{id}`
  - `POST /api/v1/pockets`
  - `POST /api/v1/pockets/{id}/transfer` (`Idempotency-Key`)
- **Eventos:** no consume.
- **Errores a mostrar:** `VALIDATION_ERROR`, `NOT_FOUND`, `CONFLICT`, `INSUFFICIENT_FUNDS` con
  mensaje accionable.

## Reglas de negocio

- El cliente no calcula rendimiento ni redondeo; si el backend los expone, solo los muestra.
- La barra de meta usa `balance_minor`/`target_minor` del servidor; si falta, se oculta.
- El traspaso exige monto > 0 y origen/destino distintos; la validacion final es del servidor.
- No se muestran cuentas completas; solo enmascaradas.
- Sin logica offline; error -> reintentar.

## Criterios de aceptacion (CA)

- `CA-01` (HU24 CA-01): el cliente ve la lista de bolsillos con saldo/moneda/meta y puede abrir uno
  nuevo.
- `CA-02` (HU24 CA-04): puede traspasar desde/hacia una cuenta o bolsillo y ve el resultado; envia
  `Idempotency-Key`.
- `CA-03`: la pantalla cubre cargando/vacio/error/contenido; datos enmascarados.
- `CA-04`: no hay calculos de negocio en el cliente; `flutter analyze` limpio y `flutter test` verde.

## Pruebas requeridas

- Navegacion: back `pop` en pantallas apiladas; raiz/tab sin back.
- Sin calculo de saldo/rendimiento en el cliente.
