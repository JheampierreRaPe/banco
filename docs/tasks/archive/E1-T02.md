## Objetivo
Exponer `/auth/kyc/challenge` y `/auth/kyc/submit` como proxy del microservicio KYC, de modo que
el dispositivo nunca reciba ni use la API key del servicio.

## Contexto embebido
- Liveness solo en onboarding (D07).
- Respuestas con formato de `docs/05` (`data`, `error.code`).
- El endpoint acepta documento + segmentos de liveness y devuelve `overall_result`.

## Context pack
- L0. L1: `docs/modules/README.md#identity`.
- L2: `docs/05-contratos-api.md#61-identidad-y-kyc-identity---hu01-hu04`,
  `docs/05-contratos-api.md#8-integracion-con-el-microservicio-kyc-consumo`.

## Frontera
- Puede tocar: `backend/app/modules/identity/api/`, `schemas/`, `service/`.
- Prohibido: modulos `accounts`, `ledger`.

## API
- `POST /auth/kyc/challenge` -> `{token, steps, expires_in}`.
- `POST /auth/kyc/submit` -> resultado del KYC.
- Errores: `VALIDATION_ERROR`, `KYC_UNAVAILABLE`.

## Reglas
- Rate limit por IP/dispositivo.
- Validar tamano y formato de las imagenes antes de reenviar.

## CA
- `CA-01..CA-03` de HU01.

## Pruebas
- Challenge valido; submit exitoso; payload invalido; servicio caido.
