## Objetivo
Implementar la fachada `send(canal, destinatario, plantilla, datos)` con implementacion mock y
registro de entrega, lista para reemplazar por un proveedor real.

## Contexto embebido
- Multi-canal desacoplado (push/correo/SMS).
- Debe tolerar caida de un proveedor sin perder mensajes.
- Registrar estado en `notifications`.

### Aditivo: proveedor SMS real Twilio con fallback al mock (2026-09-18)
```

  POST Twilio Messages.json con From/To/Body, Basic Auth, timeout 10 s sin
  reintentos propios) + seleccion por env SMS_PROVIDER=mock|twilio (default
  mock) via service.default_sender(); .env.example documenta las 4 vars.

  tests/test_notification_sender_twilio.py 10/10 verde (MockTransport, sin
  llamadas reales); tests/test_notifications_adapter.py sin regresion.
Decisiones/supuestos: 201->OK(provider_ref=SID); 4xx->NotificationValidationError
  (ValueError: la fachada no reintenta); timeout/5xx->NotificationProviderError
  (reintentable); recipient E.164 con prefijo '+' validado antes de la red;
  en 4xx no se propaga el mensaje de Twilio (puede ecoar el numero: solo
  http status + code numerico); logs solo canal+SID, sin PII ni secretos.
Pendientes/riesgos: activar SMS_PROVIDER=twilio requiere cuenta Twilio con
  numero From verificado y saldo; el destino debe estar en E.164.
Archivos afectados: app/adapters/notification_sender.py (aditivo),
  app/modules/notifications/service/__init__.py (aditivo minimo, firmas
  intactas), backend/.env.example (aditivo), tests/test_notification_sender_twilio.py
  (nuevo). Sin endpoints/eventos nuevos; mock intacto por defecto.
```
