## Objetivo

Exponer `POST /api/v1/auth/pin-reset` (`email + DNI + OTP -> fijar PIN`) para el usuario que
recupera el acceso pero no recuerda su PIN; aplicar la migracion Alembic que deja
`identity.users.email` **NOT NULL** (coherente con "OTP solo email"); y mover a `config.parameters`
las constantes de lockout, espera de reenvio, intentos de OTP y rate-limit de recovery, con
`alembic upgrade/downgrade` OK y `alembic check` limpio.

## Alcance

- **Incluye:**
  - Endpoint `POST /api/v1/auth/pin-reset` (nuevo) + servicio + esquema: valida `email + DNI + OTP`
    (OTP `RECOVERY`), fija/actualiza `credentials.pin_hash` y responde exito; anti-enumeracion con un
    unico `401` generico; rate-limit por `email+IP`.
  - Migracion Alembic `users.email` NOT NULL (+ backfill/limpieza determinista de filas existentes
    con email NULL) y actualizacion del modelo ORM `User.email` a `nullable=False`.
  - Migracion Alembic que siembra en `config.parameters` las claves nuevas (ver Modelo de datos).
  - Lectura best-effort de esos parametros (patron `otp_service._read_int_parameter`, SQL directo a
    `config.parameters` en SAVEPOINT, fallback a la constante) y su uso en `pin_login` (lockout),
    `otp_service` (resend wait / max attempts) y `recovery` (rate-limits).
  - Pruebas: `/pin-reset`, migracion (upgrade/downgrade) y parametros.
- **No incluye:**
  - `recovery.verify` (E1-T33) y la deprecacion de `/auth/activate` (E1-T32).
  - Frontend (los briefs `F-T34`..`F-T42` consumen el endpoint), `kyc-service/`.
  - Nuevas tablas (solo se usa `config.parameters`, `identity.users`, `identity.credentials`,
    `identity.otp_codes`, `identity.access_recovery`).
  - Mover a `parameters` otras constantes fuera de la lista del dueno.

## Contexto embebido (decisiones que aplican)

- **Decision del dueno (SCR-005):** extra backend = endpoints `/pin-reset` (**email+DNI+OTP**),
  migracion para `users.email` **NOT NULL**, y mover constantes (**lockout, espera de reenvio,
  intentos de OTP, rate-limit de recovery**) a `config.parameters`.
- **Flujo de recuperacion tras SCR-005:** `POST /auth/recovery/request` (email -> OTP `RECOVERY`) ->
  `POST /auth/recovery/verify` devuelve `{user_ref, device_bound}` (E1-T33, **sin sesion**) ->
  `POST /auth/pin-reset` fija el PIN -> `POST /auth/login/pin` abre la **unica** sesion.
- **DNI nunca en claro:** `identity.users` guarda `doc_number_hash` (HMAC-SHA256, UQ). Para validar
  el DNI del request se reutiliza `kyc_onboarding.hash_document_number` (:84) y
  `normalize_document_number` (:67) y se compara con `hmac.compare_digest`; el DNI jamas se loguea
  ni se persiste.
- **Anti-enumeracion (regla dura):** un **unico** `401` generico para email no registrado, DNI que
  no coincide, sin OTP, codigo incorrecto, OTP vencido y OTP bloqueado; no revelar cual fallo.
- **OTP:** el de `/pin-reset` es el `RECOVERY` emitido por `recovery.request`; se consume con
  `otp_service.validate_otp` (un solo uso, TTL y max intentos). El codigo jamas se persiste/responde/
  loguea.
- **Sesion unica:** `/pin-reset` **no** abre sesion (no crea `sessions` ni tokens); solo fija el PIN.
- **PIN:** hash con `pin_login.hash_pin` (PBKDF2-HMAC-SHA256, stdlib; no se guarda en claro); se
  resetean `failed_attempts`/`locked_until`; formato 4-6 digitos (422 si es debil, sin oraculo).
- **`access_recovery`:** registrar el reseteo con `new_credential_set=true` (es un cambio de
  credencial real), a diferencia de `recovery.verify`.
- **Parametros (regla de oro 6):** hoy son constantes/env:
  - `pin_login.LOCKOUT_SECONDS = 900` y `pin_login.MAX_FAILED_ATTEMPTS = 5` (`pin_login.py` :99/:103);
  - `otp_service.OTP_RESEND_WAIT_SECONDS = 30` y `otp_service.OTP_MAX_ATTEMPTS = 3` (`otp_service.py` :78/:83);
  - `recovery.recovery_request_rate_limit_cfg` (:161) y `recovery_verify_rate_limit_cfg` (:174)
    (env `RECOVERY_*_RATE_LIMIT_*`).
  Se leen con el patron ya existente `otp_service._read_int_parameter` (:154, SQL directo a
  `config.parameters` dentro de SAVEPOINT, fallback a la constante). `otp.ttl_seconds` y
  `otp.max_resends` **ya** estan sembradas en `0001_init_schemas.py` y no se duplican.
- **Migracion:** `identity.users.email` hoy es **nullable** (`0012_identity_core.py` :38); el ORM
  `User.email` tambien (`models/__init__.py`). Head actual = `0017_identity_access_recovery`.
  Migraciones en `backend/migrations/versions/` (NO `alembic/versions`).
- **Reglas de oro:** sin PII/DNI/OTP/PIN en logs, sin secretos, sin `float`; un modulo no toca tablas
  de otro; `alembic check` limpio (modelo ORM == BD).

## Reglas de negocio

- `/pin-reset` resuelve el usuario por email normalizado (`strip().lower()`); si no existe o
  `status != 'ACTIVE'` -> `401` generico (sin revelar existencia/estado). Si existe, valida
  `hash_document_number(doc_number)` contra `users.doc_number_hash` con `hmac.compare_digest`; no
  coincide -> mismo `401` generico.
- Solo con email+DNI validos se consume el OTP `RECOVERY` (`validate_otp`): codigo incorrecto/
  vencido/bloqueado -> mismo `401` generico. El PIN se valida en formato (4-6 digitos) antes de
  consumir el OTP (422, sin oraculo de cuenta).
- Al exito: `credentials.pin_hash = hash_pin(pin)`, `failed_attempts=0`, `locked_until=None`,
  `access_recovery` con `new_credential_set=true`, auditoria best-effort, `flush` sin `commit`
  (el endpoint confirma; revierte ante error inesperado). No crea `sessions` ni tokens.
- Rate-limit por `email+IP` verificado **antes** de la existencia (mismo patron/anti-enumeracion que
  `recovery`), con los parametros de `config.parameters`.
- Las constantes migradas se leen best-effort: sin acceso a `config.parameters` o valor invalido,
  rigen las constantes actuales (comportamiento identico); nunca romper la transaccion del llamante.
- `users.email` NOT NULL: el upgrade debe manejar de forma determinista las filas existentes con
  email NULL (estrategia documentada; p. ej. eliminar/backfill no-PII de usuarios no activables) y
  el downgrade vuelve a nullable. El ORM `User.email` queda `nullable=False` para que `alembic check`
  siga limpio.
- Sin PII/DNI/OTP/PIN en logs; sin secretos; sin `float`.
