## Objetivo

Construir el flujo Flutter de transferencia (seleccion de origen/destino, monto/concepto,
confirmacion y comprobante) contra los endpoints de `transactions`, con `Idempotency-Key` en los
POST de dinero y con los 4 estados (carga/vacio/error/exito) cubiertos.

## Alcance

- **Incluye:** feature `lib/features/transfers/` (`data/`, `models/`, `presentation/`,
  `transfers_routes.dart`), servicio sobre `ApiClient`, pantallas de destino, confirmacion y
  comprobante, manejo de errores de negocio (`INSUFFICIENT_FUNDS`, timeout interbancario con
  seguimiento), estados de UI y accesibilidad.
- **No incluye:** agenda de beneficiarios (`E2-T15`), reto biometrico (`E2-T21`), backend
  (`E2-T07`..`E2-T10`), export PDF de cuenta (`E2-T03`, ya `Hecho`).

## Modelo de datos

Sin persistencia local de dinero. Modelos Dart de respuesta (transaction_id, status, amount_minor,
currency, fee_minor, external_ref, receipt). No guardar frames ni PII en disco.

## API / eventos

- **Endpoints consumidos:**
  - `POST /transfers/own` y `POST /transfers/third-party` (`Idempotency-Key`).
  - `POST /transfers/interbank` (202) + `GET /transactions/{id}` (seguimiento).
  - `GET /transactions/{id}/receipt`.
- **Eventos emitidos/consumidos:** ninguno (el cliente no publica eventos).
- **Errores de negocio a mapear:** `INSUFFICIENT_FUNDS`, `NOT_FOUND`, `NOT_AUTHORIZED`,
  `VALIDATION_ERROR`, `TRANSFER_TIMEOUT`/`INTERBANK_UNAVAILABLE`, `409` idempotencia.

## Reglas de negocio

- Seleccion de origen entre las cuentas propias (`GET /accounts`); destino propio, a tercero o
  interbancario.
- Confirmacion muestra monto total (`amount + fee`) tal como lo devuelve el backend; el cliente
  no suma saldos ni comisiones.
- Comprobante se descarga/visualiza solo si la transaccion esta ejecutada; para `REJECTED`/`FAILED`
  se muestra el motivo.
- Reintentos de red reutilizan la misma `Idempotency-Key` del intento en curso.

- Camino feliz: flujo destino -> monto -> confirmacion -> comprobante con servicio mockeado.

- Idempotencia: un reintento reutiliza la misma `Idempotency-Key` (prueba del servicio/controlador).
