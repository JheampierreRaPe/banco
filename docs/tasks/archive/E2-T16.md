## Objetivo

Verificar con pruebas automatizadas el CRUD de beneficiarios (busqueda, tope pre-aprobado, edicion
y eliminacion), el cifrado de datos sensibles y el aislamiento por titular.

## Alcance

- **Incluye:** suite de integracion API que cubre busqueda indexada, aplicacion/exencion del tope,
  edicion, soft-delete, RBAC y cifrado en reposo; prueba de UI opcional para busqueda/agrupacion.
- **No incluye:** QA de transferencias (`E2-T12`) ni de pagos sensibles (`E2-T22`).

## Contexto embebido (decisiones que aplican)

- El tope solo lo edita el titular autenticado; busqueda `< 1 s` (`docs/07#hu07...`).
- Datos cifrados: el CCI/documento no puede quedar en claro en BD ni en logs
  (`docs/15#3`).
- Los datos de prueba son simulados, sin PII real (`docs/15#12`).
- Prohibido borrar o aflojar pruebas para ocultar bugs (`docs/16#2`).

## Modelo de datos

Verifica `accounts.beneficiaries` (cifrado, indices, `status`), `accounts.account_balances` y, para
el tope, `transactions`/`transaction_status_history` (lectura). Usa el seed de
`backend/tests/factories.py`.

## API / eventos

- **Endpoints ejercitados:** `/beneficiaries` (GET/POST/PUT/DELETE) y `POST /transfers/third-party`
  para verificar la exencion del tope.
- **Eventos verificados:** `beneficiary.saved` en `outbox`.
- **Errores verificados:** `NOT_FOUND`, `NOT_AUTHORIZED`, `VALIDATION_ERROR`,
  `DUPLICATE_BENEFICIARY`.

## Reglas de negocio

- Verificar que el CCI guardado se descifra correctamente para operar y se enmascara al listar.
- Verificar que la busqueda por alias y por nombre encuentra el registro correcto y no cruza
  beneficiarios de otro usuario.
- Verificar que el tope, cuando alcanza, omite `PENDING_AUTHORIZATION`; cuando se excede, la
  transferencia sigue la ruta de autorizacion.

## Criterios de aceptacion (CA)

- `CA-01` a `CA-04` de HU07 con evidencia por prueba.
- Regla de busqueda `< 1 s` y tope editable solo por el titular.

## Pruebas requeridas

- Camino feliz: alta, busqueda (alias/nombre), edicion, soft-delete, exencion por tope.
- Errores: ajeno -> `403`; inexistente -> `404`; duplicado; CCI invalido; tope con moneda distinta.
- Seguridad/idempotencia: CCI nunca en claro en BD/logs; doble alta con misma clave no duplica;
  busqueda no filtra datos de terceros.
