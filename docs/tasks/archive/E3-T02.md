## Objetivo

Crear la infraestructura de datos del catalogo `credits.loan_products` (modelo SQLAlchemy,
repositorio, migracion Alembic y semilla configurable) y una **fachada interna** de lectura que
expone los productos habilitados con sus tasas y topes, sin cablear valores en el codigo.

## Alcance

- **Incluye:** migracion Alembic que crea el schema `credits` (si no existe) y la tabla
  `loan_products`; modelo, repositorio y semilla idempotente de productos demo; validaciones de
  rango; fachada `list_products(session)` / `get_product(session, code|id)`.
- **No incluye:** motor de calculo (`E3-T01`), endpoints (`E3-T03`), `loan_applications`
  (`E3-T08`), UI.
- **No incluye:** `loans`, `loan_schedules`, `loan_payments`, `contracts` (son HU11/HU12, Sprint 3;
  ver `docs/08`).

## Modelo de datos

`credits.loan_products` (`docs/03b#81`): `id`, `code` (UQ), `name`, `tcea`, `tea`,
`insurance_rate`, `min_amount_minor`, `max_amount_minor`, `min_term_months`, `max_term_months`,
`allowed_terms` (`SMALLINT[]`), `enabled` (IDX), `created_at`, `updated_at`. Enum
`loan_application_status` (`docs/03b#1-catalogo-de-enums-valores-permitidos`) se declara aqui si
hace falta para el schema, aunque `loan_applications` sea de `E3-T08`. Migracion nueva + `alembic
check` limpio.

## API / eventos

- **Endpoints:** ninguno publico (el catalogo se expone en `E3-T03`).
- **Fachada interna:** `list_products(session, *, only_enabled=True)`,
  `get_product(session, *, code=None, product_id=None)`.
- **Eventos emitidos/consumidos:** ninguno.
- **Errores de negocio:** `NOT_FOUND` (producto inexistente), `VALIDATION_ERROR` (rangos
  invalidos: `min > max`, tasas negativas, plazos invalidos).

## Reglas de negocio

- `enabled=True` por defecto; los deshabilitados no se listan a clientes pero el admin puede
  consultarlos.
- Validar `min_amount_minor <= max_amount_minor`, `min_term_months <= max_term_months`,
  `tcea >= 0`, `tea >= 0`, `insurance_rate >= 0`; `allowed_terms` (si existe) dentro del rango.
- `code` unico y estable (clave de negocio); la semilla es idempotente (upsert por `code`).
- Sin PII: el catalogo es publico.

## Criterios de aceptacion (CA)

- `CA-01`/`CA-02` de HU09 (parte de datos): existe catalogo de productos con tasas y topes
  configurables; el simulador puede tomar una tasa del producto.
- El catalogo se lee por fachada, sin `JOIN` entre schemas ni imports de modelos ajenos.
- Un cambio de tasa/tope en datos no requiere despliegue.

## Pruebas requeridas

- Camino feliz: sembrar 2-3 productos demo y listarlos; `get_product(code)` devuelve el esperado.
- Errores: rango invalido -> rechazo; `code` duplicado -> conflicto de UQ; producto inexistente
  -> `NOT_FOUND`.
- Idempotencia: correr la semilla dos veces no duplica productos (upsert por `code`).
