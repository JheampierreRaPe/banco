## Objetivo

Verificar con pruebas automatizadas la **integridad del documento** (el `doc_hash` corresponde al
contenido y es reproducible), la **no reutilizacion del token biometrico** (`nonce` de un solo uso;
una firma/ token no se acepta dos veces), el **sello/no repudio** (`SIGNED` + `signed_at`) y que la
firma **no mueve dinero** ni crea `loans`/asientos.

## API / eventos

- **Endpoints ejercitados:** `POST /credits/applications/{id}/contract`,
  `GET /credits/applications/{id}/contract`, `POST /credits/applications/{id}/sign/challenge`,
  `POST /credits/applications/{id}/sign`.
- **Eventos verificados:** `credit.contract.generated`, `credit.contract.signed` (via `outbox`).
- **Errores verificados:** `CONFLICT` (no `APPROVED`, ya `SIGNED`, clave con cuerpo distinto),
  `NOT_AUTHORIZED` (firma/binding generico), `EXPIRED_NONCE` (vencido/reutilizado), `NOT_FOUND`
  (ajeno/inexistente, neutro), `VALIDATION_ERROR`.

## Reglas de negocio

- `doc_hash` **reproducible**: regenerar con las mismas condiciones da el mismo hash; cambiar un
  campo o el monto lo cambia (integridad).
- `nonce` de un solo uso: reutilizarlo (`sign` dos veces con el mismo `nonce`) -> `EXPIRED_NONCE`/
  rechazo sin cambiar el contrato.
- **Token no reutilizable:** el mismo token biometrico no firma un segundo contrato ni re-firma el
  mismo.
- Una firma por contrato: contrato ya `SIGNED` -> `CONFLICT`; el sello (`signed_at` + `doc_hash` +
  `signature_token_hash`) queda persistido.
- Firma invalida -> no cambia `status` ni mueve dinero; sin oraculo.
- Correo best-effort: una sola copia por firma; caido el sender, la firma sigue `SIGNED`.
- Doble `POST .../sign` con la misma `Idempotency-Key` -> una firma y una copia.
- Aislamiento: 0 filas en `loans`/`loan_schedules`, 0 `transactions`/`postings` nuevas.

## Criterios de aceptacion (CA)

- `CA-01` a `CA-04` de HU11, cada uno con al menos una prueba.
- Integridad y no reutilizacion tienen prueba dedicada (no solo el camino feliz).

## Pruebas requeridas

- Camino feliz: `APPROVED` -> contrato `GENERATED` -> firma valida -> `SIGNED` + sello + copia.
- Integridad: hash reproducible y sensible al contenido; el PDF descargado existe.
- No reutilizacion: `nonce` reutilizado y token reutilizado -> rechazo; contrato permanece `SIGNED`
  una sola vez.
- Errores: firma invalida -> rechazo generico; contrato ya `SIGNED` -> `409`; no `APPROVED` -> `409`;
  ajeno -> `404` neutro; correo caido -> firma `SIGNED` + notificacion `FAILED`.
- Idempotencia: doble `POST .../sign` -> una firma y una notificacion.
- Aislamiento: sin `loans`/dinero.
- Sin PII en logs.
