## Objetivo

Dejar la estructura base de la app Flutter: tema, navegacion con guardas de sesion, capa HTTP con
interceptores y manejo estandar de errores, sin logica de negocio.

## Alcance

- **Incluye:** proyecto, tema, `go_router` con guardas, cliente `dio`, manejo de errores y estados
  de carga/vacio.
- **No incluye:** pantallas de negocio (KYC, cuentas, pagos).

## Contexto embebido (decisiones que aplican)

- El dispositivo **no** ejecuta modelos de IA (no incluir analisis de imagen local).
- Toda accion que mueve dinero usa `Idempotency-Key`.
- Nunca embeber API keys de servicios en la app.
- Datos sensibles enmascarados por defecto.

## Reglas de negocio

- Los tokenes se guardan en `flutter_secure_storage`.
- El interceptador agrega `Authorization`, `X-Request-Id` e `Idempotency-Key` cuando corresponde.
- Toda pantalla tiene estados: cargando, vacio, error, contenido.
