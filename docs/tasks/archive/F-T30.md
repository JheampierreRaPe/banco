## Objetivo

Definir una **fuente unica** de la version de la app (Dart + `--dart-define`, sin dependencias nuevas) y mostrarla de forma discreta y legible en las pantallas de **entrada** (`/entry`, con "Iniciar sesion" / "Crear cuenta"), **iniciar sesion** (`/login`) y **crear cuenta** (`/kyc`), para confirmar que build esta instalado. Ademas, dejar el **esquema de versionado** acordado documentado en `docs/18-gestion-de-cambios.md` y registrar la solicitud como `SCR-004`.

## Alcance

- **Incluye:**
  - Una constante Dart como fuente unica de la version (`kAppVersion`) alimentada por `--dart-define=APP_VERSION`, con default `1.1.010` (texto visible).
  - Alinear `frontend/pubspec.yaml` (`version: 1.1.10+1`; ver nota de semver en Reglas).
  - Un widget compartido pequeno (`AppVersionLabel`, `Key('app-version')`) que renderice algo como `Version 1.1.010`.
  - Montar ese widget en las TRES pantallas relevantes:
    - `frontend/lib/features/welcome/entry_page.dart` (`/entry`; es la que el dueño vera primero).
    - `frontend/lib/features/login/login_page.dart` (`/login`).
    - `frontend/lib/features/kyc/presentation/kyc_start_page.dart` (`/kyc`, "Verificar identidad" = crear cuenta).
  - Pruebas de widget de que la version aparece en las tres pantallas y que cambiar la constante/dart-define cambia el texto sin tocar las pantallas.
  - Nueva seccion "Versionado visible de la app" en `docs/18-gestion-de-cambios.md` con el esquema literal del dueño.
  - Fila `SCR-004` en la tabla de SCR de `docs/18` (fecha `2026-09-20`, decision `entra ahora`, Sprint 1, estado `en curso`).
  - Anotar la convencion de versionado en la tabla "Decisiones ya tomadas" de `docs/README.md` (si corresponde).
- **No incluye:**
  - Leer la version desde el paquete (`package_info_plus` u otra dependencia): **no se agregan dependencias**.
  - Versionado o cambios en el panel web/admin, backend, `kyc-service/` u otros features no listados.
  - Cambios de logica de entry/login/KYC, del flujo de biometria, de la camara o del fix de camara (`F-T24`/`F-T25`).
  - Rediseno visual de las pantallas; solo se agrega una etiqueta discreta.

## Contexto embebido (decisiones que aplican)

- **Esquema de versionado acordado por el dueño (literal):**
  - Arrancar en `1.1.010`.
  - Mientras se corrige el error actual (camara KYC), cada nueva version sube `+0.0.001` (`1.1.011`, `1.1.012`, ...).
  - Una vez funcional y se pase a otros apartados del Sprint 1 que deben verse en Flutter, se varia a `0.1.0`.
  - Al acabar el sprint, `1.0.0`.
  - Este esquema debe quedar en la documentacion (`docs/18-gestion-de-cambios.md`).
- **Fuente unica:** la version se define en UN solo lugar (constante Dart `kAppVersion` + `--dart-define=APP_VERSION` con default `1.1.010`). Cambiar la version por build debe ser trivial (editar/definir en un solo punto) y NO debe requerir tocar las pantallas. Las tres pantallas montan el MISMO widget compartido; **el valor mostrado (`kAppVersion`) es el que manda para identificar el build**.
- **`pubspec.yaml` y semver:** el `version:` de pubspec no acepta cero a la izquierda en el patch, por lo que se usa `version: 1.1.10+1`; el TEXTO visible debe ser `1.1.010`, proveniente de la fuente unica (`kAppVersion`, sobreescribible por `--dart-define=APP_VERSION=...`). Dejar explicita esta correspondencia.
- **Montaje en tres pantallas:** la etiqueta se monta en `entry_page.dart` (`/entry`), `login_page.dart` (`/login`) y `kyc_start_page.dart` (`/kyc`). "Crear cuenta" abarca dos puntos: el boton en `entry_page` y el flujo en `kyc_start_page`.
- **Reglas de frontend** (`docs/13#12-reglas-de-frontend`): el dispositivo no ejecuta modelos de IA; nunca se embebe API key; los datos sensibles se muestran enmascarados. La version visible NO es dato sensible pero tampoco debe exponer informacion interna.
- **Estados obligatorios por pantalla** (`docs/20#7`): cargando, vacio, error y contenido. La etiqueta de version debe verse en el estado de contenido y no romper los demas (entry, login y crear cuenta manejan su propio estado de carga/error; la etiqueta no debe impedir ver el error).
- **Diseno "Eucalipto y Ocre"** (`docs/design/design.md`): usar los tokens existentes; la etiqueta debe ser discreta (`label-sm`, color de texto secundario) y respetar el ritmo de espaciado de 4px; no introducir colores ni fuentes nuevas.
- **Cliente delgado** (`docs/19#4-cliente-delgado-estricto`): es solo presentacion; no hay logica de negocio, red, ni persistencia asociada a la version.

## Reglas de negocio

- `kAppVersion` es la **unica** fuente de la version mostrada: `const String kAppVersion = String.fromEnvironment('APP_VERSION', defaultValue: '1.1.010');` (el `defaultValue` es la version vigente del esquema y **el texto mostrado que identifica el build**).
- El texto visible lo produce el widget compartido a partir de esa constante; ninguna pantalla contiene cadenas de version ni numeros hardcodeados.
- Cambiar la version por build = editar el `defaultValue` (o pasar `--dart-define=APP_VERSION=1.1.011`) en un solo lugar; NO se editan las pantallas.
- `frontend/pubspec.yaml` usa `version: 1.1.10+1` porque pub/semver no acepta cero a la izquierda en el patch; el texto visible sigue siendo `1.1.010` desde `kAppVersion`. Documentar la correspondencia `1.1.10+1` (pubspec) ↔ `1.1.010` (mostrado).
- La etiqueta se monta en las TRES pantallas (`/entry`, `/login`, `/kyc`) con el mismo widget y `Key('app-version')`.
- La etiqueta es discreta y no intrusiva: no debe tapar acciones ni romper los estados obligatorios (cargando/vacio/error/contenido).
- No se agregan dependencias nuevas a `pubspec.yaml`.
- No hay logica de negocio, red ni persistencia asociada (cliente delgado).
