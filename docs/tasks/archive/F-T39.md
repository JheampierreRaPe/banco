## Objetivo

Reordenar y redisenar el cierre del registro: **crear PIN (`0:497`) -> confirmar PIN (`0:604`) ->
acceso biometrico (`0:704`) -> OTP -> `registro exitoso` (`0:740`)**, con el estilo "Eucalipto y
Ocre", y mover `saveUserRef` para que se ejecute **solo en el paso success** (hoy se guarda temprano
en `kyc_result_page.dart:149`).

## Reglas de negocio

- Orden obligatorio del flujo: **crear PIN -> confirmar PIN -> acceso biometrico (opcional) -> OTP ->
  success**. El paso biometrico es una **oferta** (gate local); su rechazo/cancelacion cae a PIN y no
  bloquea el registro.
- **`saveUserRef` se ejecuta SOLO en el paso success** (`0:740`), con el `userId` del resultado KYC;
  no antes. Si falla el secure storage, best-effort: se avisa y no se inventa el `user_ref`.
- Confirmar PIN debe coincidir con el PIN creado (validacion de UI, no de negocio); el backend es
  quien valida OTP/PIN y activa.
- Datos sensibles enmascarados; PIN/OTP nunca en logs, autofill ni sugerencias; objetivos tactiles
  >= 44px.
- Sin logica de negocio, sin validar OTP/PIN en el cliente, sin credenciales hardcodeadas.
- Sin dependencias nuevas ni cambios de contrato.
