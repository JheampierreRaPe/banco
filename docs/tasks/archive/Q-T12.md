## Objetivo

Completar el CI: (a) **medir cobertura** con `pytest-cov` y fijar un **umbral** (`--cov-fail-under`);
(b) integrar al pipeline los tests/lint del **frontend Flutter** (`flutter analyze`, `flutter test`)
y del **panel `admin-web`** (`npm ci`, `npm run lint`, `npm test`, `npm run build`), que hoy NO
corren; (c) mantener/extender el job agregador `ci-success` para que falle si cualquiera falla.

## Reglas de negocio

- Medir **primero** la cobertura real; el umbral (`--cov-fail-under`) se fija despues, con un valor
  alcanzable y justificado (no magic number).
- Todo job nuevo con **fallo explicito** (sin `continue-on-error`).
- `ci-success` depende de **todos** los jobs (incl. Flutter y panel) y falla si alguno no es
  `success`.
- Frontend y panel usan lockfiles (`pubspec.lock`/`package-lock.json`) para builds reproducibles.
- **No borrar pruebas para pasar** ni reducir el umbral para dejarlo verde.

## Criterios de aceptacion (CA)

- `CA-01`: la cobertura se mide con `pytest-cov`; `pytest --cov=app --cov-fail-under=<N>` corre en
  CI y en local; el valor real medido y el umbral elegido quedan documentados.
- `CA-02`: el pipeline corre `flutter analyze` y `flutter test` sobre `frontend/`.
- `CA-03`: el pipeline corre `npm ci`, `npm run lint`, `npm test` y `npm run build` sobre
  `admin-web/`.
- `CA-04`: `ci-success` incluye los jobs nuevos en `needs` y falla si cualquiera falla (verificado
  forzando un fallo).

## Pruebas requeridas

- **Panel:** `cd admin-web; npm ci; npm run lint; npm test; npm run build` -> verde.
